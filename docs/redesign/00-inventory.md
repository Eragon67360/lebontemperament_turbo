## a) Feature inventory

### a.1 Shell and navigation

##### Layout stack

`app/layout.tsx` (`<html lang="fr">`, Inter via `next/font/google`, `<Analytics>` placed **before** `<body>` as a sibling of it, `overflow-y-hidden` body, `Toaster position="top-right" richColors`, `Providers`) → `app/providers.tsx` (`QueryClientProvider` with the module singleton `lib/query-client.ts`: staleTime 5 min, gcTime 10 min, retry 2, refetchOnWindowFocus; `AnimatePresence mode="wait"` wrapping children; `ReactQueryDevtools`) → `app/dashboard/layout.tsx` → `components/layouts/ProtectedLayout.tsx` (server: `checkAuthorization()`; 401 → `/auth/login`, 403 → `/unauthorized`) → `components/DashboardShell.tsx` (client; owns `messagesDialogOpen` and `bugReportDialogOpen` state; renders `MobileSidebar`, desktop `Sidebar` in a `hidden md:block md:w-64` column, `DashboardMainContent`, then `MessagesDialog` and `BugReportDialog` outside the sidebar) → `components/DashboardMainContent.tsx` (`<main>` rounded-2xl white card, `bg-white/50` on `/dashboard` only; `BreadcrumbNav` then a scroll container `px-2 md:px-6` with `PageTransition`). There is no other `layout.tsx` (auth pages render bare, no shared auth layout). `app/dashboard/loading.tsx` → `PageSkeleton`; `app/dashboard/error.tsx` → `ErrorState` with retry; `app/not-found.tsx` → `EmptyState` on the same gradient; `app/error/page.tsx` is a bare `<p>` (no shell, no styling); `app/unauthorized/page.tsx` hand-rolled with `bg-gray-50`, `text-gray-*` and a mailto whose address is mistyped (`(a personal address, mistyped)`, `app/unauthorized/page.tsx:78`).

Page background: `from-primary/10 to-primary/50 bg-gradient-to-br` on the shell (`DashboardShell.tsx:22`), repeated on `not-found.tsx:10` and the login page (`app/auth/login/page.tsx:20`, with `via-primary/5 to-background`).

##### Breadcrumbs (`components/BreadcrumbNav.tsx`)

Built from `buildNavSections({isSuperAdmin:true})` labels + `usePathname()`. Always prefixed with "Tableau de bord" (link). Hidden entirely on `/dashboard` (crumbs empty → `null`), so the main card there has no top bar. Mobile: only the last two crumbs are visible (`hidden sm:flex` on earlier ones), separators hidden accordingly; `text-xs sm:text-sm`, `flex-nowrap` with truncation. Rendered inside `<main>` at `px-4 pt-3 md:px-6`, i.e. **above** the page's own `PageShell` title, with no visual connection to it.

##### Page header pattern (`components/layouts/PageShell.tsx`)

Props: `children`, `className`, `contentClassName`, `title?`, `description?`, `headerAction?: ReactNode`, `fullHeight?: boolean` (default false; true = `h-full min-h-0 grow overflow-hidden`, header `mb-4 shrink-0`), `theme?: "admin" | "members" | "public" | "anniversary" | "default"`. Wrapper `mx-auto w-full max-w-7xl flex-col gap-6`. Header: `flex-col gap-3 sm:flex-row sm:items-center sm:justify-between`; `h1` is `text-xl font-bold tracking-tight sm:text-2xl` **plus a per-theme gradient text** (`PageShell.tsx:29`): admin blue (`from-blue-600 to-blue-500`), members purple, public green, anniversary teal→pink, default `text-gray-900`. `description` is `text-muted-foreground text-sm leading-relaxed`. Theme also adds `theme-admin|members|public` classes that set `--theme-color` HSL variables (`globals.css:130`), which **nothing reads** (grep: no `var(--theme-color)` anywhere). Cards accept `variant="admin|members|public"` → `card-theme-*` top border in the same blue/purple/green.

Usage: 26 of 26 dashboard pages import `PageShell` (measured). Themes in use: anniversary 11, public 7, members 5, admin 4, dashboard root none. Two pages pass a non-title string as `title` of an `EmptyState` only (grep artefact: `memories` "Aucun témoignage", `travail/[programId]` "Aucun groupe"); real titles are e.g. "Gestion des utilisateurs", "Compte-rendus de CA", "Prochains concerts", "Chronologie - 40 ans d'histoire", "Statistiques héro" (nav says "Statistiques Hero"), "Configuration du formulaire" (nav "Configuration formulaire"), "Vidéos" (nav "Galerie vidéos"), "Gestion des événements" (nav "Événements"), "Gestion des répétitions" (nav "Répétitions"), "Anniversaire 40 ans" (nav "Gestion de la page"). The dashboard root uses `DashboardWelcomeHeader` instead: a mobile `h1` "Bonjour, <name>" and a desktop "iPhone-notch" tab in hard-coded `#c9e2e4` with two SVG wings (`components/DashboardWelcomeUser.tsx:32-75`), `-mx-6 -mt-6` negative margins to overlap the main card edge; it renders **two `h1` elements** (one per breakpoint, hidden by CSS only).

##### `DataState` family (`components/ui/data-state.tsx`)

- `DataState({isLoading, isError, isEmpty, onRetry, errorDescription, skeleton (required), empty, children})`: error > loading > empty > children. 74 usages.
- `ListSkeleton({rows=5, className, label})`, `CardGridSkeleton({cards=6, className, label})`, `PageSkeleton({cards=6})`: each wrapped in `role="status" aria-busy` with sr-only label. 27 / 21 / 2 usages.
- `EmptyState({icon?, title, description?, action?, className})` 53 usages; `ErrorState({title?, description?, onRetry?, className})` `role="alert"`, 8 usages. Both headings are `h2 text-gray-900` (hard-coded, not `text-foreground`).

##### Mobile behaviour

`MobileSidebar` (`md:hidden`) is a 48 px top bar: menu `Button size="icon"` (40×40, under the 44 px target the nav entries themselves respect with `min-h-11`), picto and brand. Opens a `Sheet side="left"` 19 rem wide with the full `Sidebar mobile` (sections become `Collapsible`, only the active section open). Sheet closes on `pathname` change (`MobileSidebar.tsx:34`) and on item click; opening a dialog from the sheet defers `onNavigate` with `setTimeout(…, 0)` so the dialog mounts first (`SidebarNav.tsx:151`, `Sidebar.tsx:165`). Shell uses `h-dvh` and `p-2 gap-2` on phones, `p-4 gap-4` from `md`. Breadcrumb collapses to two crumbs. Dialog content caps at `max-h-[90dvh]` (`components/ui/dialog.tsx`).

##### Motion in the shell

`PageTransition.tsx`: `motion.div` opacity 0→1, y 4→0 (0 under reduced motion), 180 ms, custom ease; mounted inside `AnimatePresence mode="wait"` from `providers.tsx` but has no `key`, so there is no exit animation, only the mount fade. `DashboardWelcomeUser.tsx` fades the name in over 600 ms (no reduced-motion guard). Nav entries: `transition-[color,background-color,transform] duration-150`, chevron rotate 200 ms, `animate-ping` badge, all with `motion-reduce:` guards. Login page uses `animate-blob`, `animation-delay-2000/4000` classes that are **defined nowhere** (`globals.css` has no such rule; grep over all css returned nothing) and `animate-pulse` on the logo glow and sparkle icon with no guard.

### a.2 Screens: home, members area, organisation, auth

Conventions used in the table:

- **Auth**: every one of the 104 handlers starts with `checkAuthorization()` (`utils/auth.ts:38` → `authorize("admin")` → `decideAccess` in `utils/access.ts:43`): session user via `@supabase/ssr` server client, then `profiles.role` must be `admin` or `superadmin`; 401 `{error:"Non authentifié"}` when signed out, 403 `{error:"Non autorisé"}` otherwise. "admin" in the column means exactly that check. `checkDriverAuthorization()` (superadmin only, `utils/auth.ts:43`) exists but has **no caller**. Finer rules are noted per handler.
- **Client**: "session" = `utils/supabase/server.ts` (anon key + user cookies, RLS applies); "service" = `utils/supabase/admin.ts` (`SUPABASE_SERVICE_ROLE_KEY`, bypasses RLS). In all service-role handlers the client is created **after** the role check (`createAdminClient()` is called only after `auth.authorized`).
- **Response**: success shape then error shapes. All errors are `{error: string}` (plus `details` where noted). No handler returns stack traces.
- **Called from**: admin-side code. External callers were searched in `apps/website`, `apps/e2e`, `apps/mobile_app/lib`, `google-apps-script/`, `scripts/`: only the e2e suite (`apps/e2e/tests/admin/access-control.spec.ts`, anonymous GET → 401 on 29 routes) hits the admin API; the website calls its own `/api/*`, not the admin's.
- **Side effects** column: Cloudinary (`lib/cloudinary.ts`), Google Apps Script (`GOOGLE_APPS_SCRIPT_URL`), website revalidation (`utils/revalidateWebsite.ts`, best effort via `after()`), activity log (`activities` table insert), Supabase Storage, Supabase Auth admin.

## b) UX audit

Merged from the three crawls, grouped by what an occasional admin experiences. Each item cites where; the detailed, per-screen findings with every `file:line` are in part (a) and in the source tables. **Measured** = read in the code at `a3110c0`; **estimated** = inferred.

### b.1 Orientation: "where am I, what is this?"

- The breadcrumb sits above and apart from the page title (`DashboardMainContent.tsx:23-24`, `PageShell.tsx`), and is 8 px out of line with the content on phones.
- 10 page titles differ from their navigation label (e.g. nav "Événements" → title "Gestion des événements"; "Galerie vidéos" → "Vidéos"; "Gestion de la page" → "Anniversaire 40 ans").
- Sections are told apart by **colour** (blue admin, purple members, green public, teal→pink anniversary gradient titles: `PageShell.tsx:29`), not by structure — four extra hues against a one-accent system, and meaningless to a colour-blind user.
- Five routes are reachable only from inside pages (migration, preview, programme and group pages); routing-only segments (`/dashboard/admin`, `/dashboard/public`, …) answer "not found".
- The home page's lists look clickable but aren't (`dashboard/page.tsx:145-163, 296-377`); it renders two `h1`s (one per breakpoint).
- No search, no keyboard shortcut, no theme toggle.

### b.2 Primary action: "what can I do next?"

- Users page: three near-equal header buttons for one goal (Synchroniser, Inviter, Nouvel utilisateur: `users/page.tsx:277-319`).
- Projets: the one-off "Migrer JSON" sits next to "Nouveau projet" in the header and the empty state (`projets/page.tsx:362-376, 397-414`).
- 40 ans index: the only control is a site-wide switch wrapped in a warning, with no "what next" (`anniversary/page.tsx`).
- FileExplorer "Ajouter" doesn't say what it adds; the event form has no Cancel; the rehearsal empty state offers no create action.

### b.3 Feedback and states

- **Good**: every list uses the shared `DataState` (74 usages) with retry; skeletons carry `role="status"`.
- Hand-rolled or missing states: singleton editors (hero, form config), the preview page, the users sync dialog, `MessagesDialog`, `/error` (a bare `<p>`), `/unauthorized` (off-system, mistyped personal mailto).
- **Silent outcomes**: hero-stat save failure (`HeroStatDialog.tsx:109-111`), bug-report status change, "Envoyer le rapport".
- Misleading: the invite progress bar sits at 0 % for the whole send; "Actualisation en cours…" is a success toast for a start.
- **Side effects on view**: opening bug reports marks all read; opening Users downloads the Excel roster each visit.

### b.4 Destructive and irreversible actions

- **No confirmation**: bulk account deletion and the Excel data overwrite in the sync dialog (`SyncUsersDialog.tsx:141-221`); role change is a bare select (`UserCard.tsx:228-244`); the 40 ans publication switch flips the public page live in one click; avatar removal.
- Confirmations that don't name what they delete: concert, project, public video; tour deletion doesn't say what happens to its concerts; migration uses `window.confirm`.
- **Good**: every single-item delete in the members/admin area goes through an `AlertDialog` naming the consequence; the API refuses self-role-change, self-delete and superadmin escalation whatever the UI shows.

### b.5 Language

- Raw values and developer vocabulary: `event_type` enums on event cards, "Icône: FaMusic", "ID de la section cible", "Slug (URL)", "Ordre : N" on every card, "animation GSAP", the flag's DB name as a heading, "Migration failed", "Upload en cours (image2)…", "Erreur 403", "Ajouter un CA".
- The same thing named three ways: souvenir / mémoire / témoignage; "Contexte" (concert) vs "Type" (tour) for one enum; "approuvé" / "acceptées" / "en attente" for invitation states; "Le Bon Temperament" without its accent in the shell.
- Hints that contradict validation: SVG advertised but refused (uploads, profile picture); "URL ou l'ID" for videos where an ID fails; undocumented CSV columns for invitations.

### b.6 Forms

- Three validation regimes side by side: inline zod (concert, tour, video, event, user forms), browser-native `required` bubbles (all anniversary dialogs), toast-only (project modal, uploads, rehearsals, CA, invitations, auth); 15 forms are not on react-hook-form + zod (6 are).
- Required markers differ ("(optionnel)" vs red `*` vs `*` in the label); clearing a number field sends `NaN` (five anniversary dialogs); unsaved work is lost on Escape or a click outside, worst in the 3-tab project modal; submit labels drift (Créer / Ajouter / Enregistrer / Mettre à jour / Modifier); rehearsal submit has no pending state (double submit).

### b.7 Visual system

- 7 type sizes plus an arbitrary 10 px (mandate: 4–5); 8 radius values, and primitives disagree with each other (`Input` `rounded-xl` vs `Textarea` `rounded-md`, `Dialog` `rounded-lg`).
- ~170 raw grey utilities next to 184 `text-muted-foreground`; 21 `bg-white`; three hard-coded hex colours; no semantic success / warning / info tokens (pages use raw `bg-green-100` etc.).
- **Dark mode unreachable**: `next-themes` installed, no `ThemeProvider`; `dark:` variants in only three files; the shell hard-codes light surfaces.
- Unused: 5 `components/ui` primitives (incl. the 771-line `sidebar.tsx` and the `--sidebar*` tokens), the `--chart-*` tokens, two Geist fonts; login animation classes defined nowhere.

### b.8 Accessibility

- Icon-only controls without a name: uploader clear buttons, invitation row actions, `MessagesDialog` back/send; sync rows are `div onClick` without checkbox semantics; uploader `<label>`s not tied to their file inputs; the icon picker lacks pressed/group semantics.
- No global `:focus-visible` rule (per-component rings, some on `focus:` not `focus-visible:`); the mobile menu button is 40 px (nav entries are 44 px); `PageTransition` has no `key` (no exit); login and welcome motion without a reduced-motion guard.

## d) Proposed information architecture

**Constraint.** Every existing route path stays: deep links, bookmarks and the e2e tests depend on them. The IA changes the **navigation grouping and labels, the page headers, the breadcrumbs and the home screen**. It adds **two new routes** (marked _new_), both of which need the owner's approval. Breadcrumbs follow the new navigation labels, while URLs keep their current segments.

**Principles:**

- One section per job, named in plain French.
- One accent colour for the whole app: sections are identified by label and icon, not by colour.
- The home screen becomes a hub with three parts: what needs doing, what's coming, and one shortcut per job.
- Lists split **"À venir" and "Passés"** into tabs; the past is reachable but never mixed in.
- The two syncs (Drive and roster) become pages that **show what will change before anything is written**.
- One-off or contextual screens leave the navigation and are reached from the page they belong to.
- The campaign is a **primary** section until it's published early 2027. After that it moves under "Archives des campagnes" (a later decision).

### d.3 Risks to watch in later phases (what neither `tsc` nor today's e2e would catch)

- **Dialog mounting on mobile** (`setTimeout(…, 0)` in `SidebarNav.tsx:151`). Moving dialog triggers into a header menu needs the same care, or the sheet closes before the dialog mounts.
- **Dark mode.** Mounting `ThemeProvider` turns every hard-coded `bg-white` or grey surface wrong in dark mode, so phase 2 must sweep the shared components before enabling a toggle.
- **The two syncs touch member-facing data.** Their changes reach the website and the mobile app. They need their own tests (pure diff functions in `@repo/domain`) and an e2e against the separate staging project (#363). **Target flow:**

1. **Fetch:** one server module reads the sheet privately through the association's Google service account (the pattern the calendar sync already uses). It has a timeout and runs at request time.
2. **Validate:** a pure, unit-tested function in `@repo/domain`. It **refuses** when:
   - a required header is missing (headers are normalised: trimmed, accent- and case-insensitive, with a small alias list);
   - the row count drops below half of the active members or of the last run.

   It **warns** on duplicates, invalid emails, rows without a name, and voice values outside the agreed list. It normalises emails, phones and names ("Prénom NOM" by an explicit rule, never by splitting words).

3. **Review (_new_ page `/dashboard/admin/users/sync`).** The rows are grouped:
   - **new:** to invite;
   - **changed:** field by field, old → new, roster-owned fields only;
   - **no longer in the list:** every status;
   - **conflicts:** duplicates, no email, name-only matches proposed as suggestions (this handles changed emails without creating a second account).

   Each row has a checkbox. The destructive group is collapsed by default and shows the last sign-in.

4. **Apply:** one server call carrying the selected changes and the roster's fingerprint. The server refuses if the roster changed since the preview, then:
   - runs the updates in one transaction;
   - sends invitations in throttled batches;
   - returns a per-item result;
   - logs a sync-run row and activity entries, which the home feed shows.
5. **Removals deactivate; they don't delete.** A status such as `active | left` (additive migration, owner-applied). A deactivated member:
   - disappears from the website and app directories;
   - loses members-area access;
   - comes back automatically if their email returns to the roster.

   Hard deletion stays a separate, confirmed, superadmin-only action for erasure requests.

6. **Field ownership:** the roster owns membership, name, voice, home phone and address; the member owns their photo (and possibly their mobile phone, see open question 3). A difference on a member-owned field shows up as a conflict, never as an overwrite.

**Target design.** Drive stays the source of truth. Supabase keeps an **index** (Drive IDs and metadata), never copies of the files. Members open documents through the website's existing proxy.

1. **Admin, once:** paste the root Drive folder. "Vérifier" shows its name as the service account sees it, and warns if it isn't shared.

6. **Credentials:** the calendar sync's service account, with `drive.readonly` scope and the root folder shared with it. The website's `/api/drive/*` moves to it as well, which retires the personal refresh token.
7. **The old Storage files** are frozen (no new uploads) and counted read-only. The owner then decides: move them into Drive, or delete them. The tables and bucket are dropped in a later release.
