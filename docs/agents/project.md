## Backend: Supabase

- **Two projects**: production `website` and `website-staging` (production's structure with fake data, [supabase/staging](../../supabase/staging/README.md)). Staging, previews and Vercel's Development target use `website-staging` since 2026-10-07; production, the apps, edge functions and crons use `website` ([safety](safety.md#production-and-staging-databases)). `supabase/config.toml` holds the local CLI config.
- **Tables** (`packages/domain/src/database.types.ts`): `profiles`, `groups`, `concerts`, `events`, `rehearsals`, `programs`, `projects`, `tours`, `cas`, `activities`, `notifications`, `files`, `folders`, `drive_folders`, `youtube_links`, `feature_flags`, `bug_reports`, `bug_messages`, `donations`, `donors`, `donation_receipt_seq`, `deliveries`, `delivery_recipients`, `rehearsal_sync_logs`, `drive_index_nodes`, `drive_sync_runs`, and the `anniversary_*` CMS tables.
- **Enums**: `user_role` = `superadmin` | `admin` | `user`; `group_type` = Orchestre, Choeur complet, Tous, Hommes, Femmes, Jeunes/Enfants; `activity_type` for the admin activity feed.
- **Migrations**: `supabase/migrations/` (30 files, 2025-01 → 2026-10). They create the newer tables, each with row-level security enabled. **The core tables** (`profiles`, `concerts`, `events`, `rehearsals`, …) **predate the migration history**: their schema and RLS policies live only in the database. A root-level `migrations/create_projects_table.sql` is a leftover from before `supabase/migrations`.
- **Edge functions** (`supabase/functions/`): `sync-rehearsals-from-calendar` (Google Calendar → rehearsals, scheduled with `pg_cron` + `pg_net`), `sync-drive-index` (Google Drive → `drive_index_nodes`, nightly cron plus the admin's `POST /api/drive-sync`; setup in its README), `send-push-notification` (FCM, members), `notify-public-concerts` (daily concert pushes to the app's visitors, FCM topic `public_concerts`), the delivery-round functions (`start-delivery-round`, `optimize-recipients-route`, `send-delivery-sms`, `send-delivery-complete-sms`, `check-eta-and-send-arrival-sms`, Twilio SMS), and `purge-bug-screenshots` (removes the screenshots of signalements resolved over a year ago, before the daily `purge_expired_records()` deletes them; #355).
- **Types**: `npm run db:types` regenerates `database.types.ts` from the remote project (needs `SUPABASE_ACCESS_TOKEN`; the script writes through a temp file so a failed run can't wipe the committed types).
- **How migrations and functions reach production**: nothing in the repo automates it (no CI step, no script). Treat both as manual owner-approved operations ([release](release.md#supabase)).

## Environments

Variables are listed by **name** in `turbo.json` (`globalEnv`, `tasks.build.env`, `tasks.test:e2e.env`) and in each app's `.env.example`; values live in Vercel and in local `.env.local` files (never print them). What is shared matters most:

| Variables                                                                                                | Vercel targets                                 | Consequence                                                                                                                         |
| -------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`                 | Production; Preview and Development (staging)  | Production uses `website`; staging, previews and `vercel env pull` use `website-staging` with the new publishable and secret keys   |
| `STRIPE_SECRET_KEY`, `STRIPE_ENDPOINT_SECRET`, `NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY`                      | separate Production and Preview (`dev`) values | Used by the CD catalogue only (being removed, #318); keep Production and Preview separated                                          |
| `CLOUDINARY_*`, `GOOGLE_*`, `NEXT_PUBLIC_GOOGLE_*`, `NEXT_PUBLIC_GDRIVE_*`, `NEXT_PUBLIC_MAPBOX_API_KEY` | all environments, one value                    | Uploads, calendar and Drive changes from any environment are real                                                                   |
| `SMTP_USER` / `SMTP_PASSWORD`                                                                            | all environments                               | SMTP mailbox credentials, server-only (Sensitive). The old `NEXT_PUBLIC_BURNER_*` pair was deleted from Vercel on 2026-10-07 (#321) |
| `NEXT_PUBLIC_ADMIN_PASSWORD`                                                                             | deleted from Vercel                            | Deleted on 2026-10-01; the password is used nowhere else                                                                            |
| `POSTGRES_*`, `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_JWT_SECRET`                                 | Production only (integration)                  |                                                                                                                                     |

Mobile: `apps/mobile_app/.env` (`SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SITE_URL`, Drive folder IDs, Twilio) is generated in the Android workflow from GitHub secrets, except `SITE_URL`, which is pinned to `https://www.lebontemperament.com` there (a staging URL sits behind Vercel Authentication and breaks Partitions); locally it comes from `.env.example`.

## Known quirks

- **TypeScript versions differ on purpose**: the apps type-check with TypeScript 7 (`typescript@^7`); the root pins `5.9.3` because ESLint's parser (typescript-eslint) loads the root TypeScript and doesn't support 7 yet (measured on #417). Run type checks through `npm run check-types` (Turbo, per workspace).
- **The pre-commit hook is light** (`lint-staged`: Prettier on staged files; no build, no version bump): see [workflow](workflow.md#the-pre-commit-hook).
- **Versions** live in `version.json` and both apps' `package.json` (bumped on the release PR with `npm run release:bump`); the mobile version is in `pubspec.yaml` (`2.0.109+125` on 2026-10-01).
- **Prettier has no config file**: defaults plus `prettier-plugin-organize-imports` and `prettier-plugin-tailwindcss` from the root dev dependencies; `.prettierignore` skips shadcn's generated `components/ui/**` and lockfiles.
- **Vercel builds from the repository root** (Root Directory empty, `turbo build --filter=website` / `--filter=admin`); `apps/*/vercel.json` are never read ([DEPLOYMENT.md](../../DEPLOYMENT.md), follow-up #366).
- **`next dev` rewrites `apps/website/AGENTS.md`** (the Next.js notice block): commit it with your work rather than fighting it.
- **Tracked artefacts** worth a decision: `desktop.ini` (Windows), `portfolio-hover/` (the portfolio's tooling; other projects moved it to the portfolio repo), `migrations/create_projects_table.sql` (legacy).
- **Language**: the site, admin and app speak French to users; code, comments, docs and commit messages are in English (Conventional Commits).
